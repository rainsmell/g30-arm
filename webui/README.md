# 机械臂 Web 控制台

3D 数字孪生 + 关节控制 + 日志/Debug 的一体化网页界面。
**零新增 Python 依赖**（只用标准库 + SDK 已有的 pyserial），**零前端依赖**
（原生 JS + 自写 WebGL，不用 CDN，离线可用）。

```bash
pip install pyserial          # SDK 唯一依赖
python -m webui --open        # 打开 http://127.0.0.1:8765/
```

## 2. 启动参数

```bash
python -m webui [--host 127.0.0.1] [--http-port 8765]
                [--serial COM8] [--baud 115200]
                [--dry-run] [--auto-connect] [--open]
```

| 参数 | 说明 |
|---|---|
| `--host 0.0.0.0` | 允许局域网访问（会打印局域网地址）。⚠ 局域网内任何人都能控制机械臂 |
| `--dry-run` | 默认以 dry-run 连接：**所有写命令只记录不发送**，可以放心试界面 |
| `--auto-connect` | 启动即连接串口 |
| `--open` | 自动打开浏览器 |

也可以不用命令行，直接在页面上选串口 / 改波特率 / 勾 dry-run 再点"连接"。

### 2.1 一键启动（桌面快捷方式）

项目根目录的 `启动机械臂Web控制台.bat` 就是双击即用的启动器：

1. 切到项目目录；
2. 自动找 `py -3` / `python`（缺失时用 `pip` 自动装 `pyserial`）；
3. 执行 `python -m webui --open` —— **服务 + 页面一起启动**；
4. 服务日志留在控制台窗口里，关闭窗口即停止服务（Ctrl+C 亦可）。

额外参数会透传，例如 `启动机械臂Web控制台.bat --dry-run`。

想直接在桌面上放一个快捷方式（带图标，名为"机械臂控制台"）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\create_desktop_shortcut.ps1
```

脚本把 `.lnk` 写到当前用户桌面（图标不存在时会先调 `tools/make_icon.py` 生成）；
重复运行只会刷新同一个快捷方式（想换名字用 `-Name "别的名字"`，不想要图标加 `-NoIcon`）。

### 2.2 图标

图标是**代码画出来的矢量图形**（不用照片），源文件 `tools/make_icon.py`：

```bash
python tools/make_icon.py                    # 重新生成 tools/robot_arm.ico（7 个尺寸）
python tools/make_icon.py --preview p.png    # 看预览，不覆盖 .ico
```

设计：深色圆角方块 + 橙黄渐变机械臂（底座/肩/肘/腕/两指夹爪）+
青色转台环 + 从夹爪发出的两道信号弧（呼应"Web 控制"）。
16/24/32 px 会自动退化为**简化字形**（去配角、加粗线宽），保证小尺寸下仍可辨认。

> 图标一变，路径就是 shell 从未见过的，必然重新渲染；同时脚本会调
> `SHChangeNotify` 让资源管理器立即重读快捷方式，无需重启 explorer。
> 如果仍然显示旧图标（缓存太顽固），执行：
>
> ```powershell
> taskkill /f /im explorer.exe; start explorer.exe
> ```

## 3. 架构

```
webui/
├── model_config.py     ★ 关节控制语义 + 3D 模型几何（唯一数据源，改这里就能改模型）
├── controller.py       工作线程 + 作业队列 + 事件总线（独占串口）
├── server.py           纯标准库 HTTP + SSE 服务
├── static/
│   ├── index.html      页面结构
│   ├── style.css       深色工业风样式
│   ├── mat4.js         矩阵/向量数学（列主序，可 node 单测）
│   ├── model.js        正运动学（可 node 单测）
│   ├── viewer.js       自写 WebGL 渲染器
│   └── app.js          界面逻辑 + API 客户端 + SSE
└── README.md
```

### 3.1 后端：为什么用一个工作线程

串口是**独占资源**，而且这块板的总线有个硬约束：**运动期间读寄存器会让从站挂死**。
所以：

* 所有碰总线的操作都塞进一个 `queue.Queue`，由**唯一的工作线程**串行执行；
* HTTP 处理线程只负责入队 + 等待（快速命令）或直接返回（长动作）；
* 运动是一个"作业"，作业执行期间不会有别的读插进来 —— **这个约束由架构保证，不靠自觉**。

### 3.2 事件总线（SSE）

`GET /api/events` 是一条 `text/event-stream`，推送四类事件：

| type | 内容 |
|---|---|
| `log` | 结构化日志（level / message / detail） |
| `trace` | 原始 Modbus 帧（`tx` / `rx` + hex），由 SDK 的 `trace` 钩子产生 |
| `status` | 6 个关节的状态快照 |
| `state` | 连接状态、忙碌状态、队列长度、订阅者数 |

新页面连上时会**回放最近 200 条日志 + 当前状态**，所以刷新不会丢上下文。

### 3.3 前端：为什么自己写 WebGL

* 不依赖 CDN → 机械臂现场常常没有外网，页面必须能离线打开；
* 模型只需要长方体/圆柱/球三种图元 → 自写渲染器约 600 行足够；
* 数学和运动学抽成 `mat4.js` / `model.js`，**可以在 node 里跑单元测试**
  （`tests/test_model.js`，28 例），这是用 three.js 做不到的。

渲染特性：方向光 + 环境光 + 边缘光 + 距离雾、双面光照（不做背面剔除，避免绕序问题）、
按需渲染（只有相机/姿态/选项变化才重绘，页面挂后台不烧 GPU）。

### 3.4 渲染管线（★ 曾经踩过的坑）

着色器在**线性空间**做光照，输出前用**精确的 sRGB 传递函数**编码回显示空间：

```glsl
vec3 srgbEncode(vec3 c) {
  return mix(c * 12.92, 1.055 * pow(c, vec3(1.0/2.4)) - 0.055,
             step(vec3(0.0031308), c));
}
```

早期版本把材质色做了 sRGB→线性转换，却**忘了编码回 sRGB**，
结果整个机械臂渲染成接近纯黑 —— 在深色背景上完全看不见。
现在 `tests/test_model.js` 里有一组"可读性"用例专门防这个回归：
它拿真实调色板离线算出每个材质的最终屏幕亮度，断言：

* 最坏情况（朝下的面 + 无主光）也必须比背景亮 ≥15%；
* 典型光照下亮度 > 0.28；
* 本体亮度 > 地面网格线亮度 × 2；
* 1 m 处雾混合 < 30%；
* 描边色同时与背景、与本体都有足够亮度差。

另一个只靠眼睛很难发现的坑：描边用 **inverted hull**（放大外壳 + `cullFace(FRONT)`），
**依赖所有三角形从外面看是逆时针绕序**。早期圆柱侧面的绕序是反的，
那会让外壳盖住本体、整条臂变成一片描边色。
`tests/test_model.js` 现在逐个三角形校验绕序与法线方向一致。

## 4. 3D 模型与标定

### 4.1 模型从哪来

几何尺寸是按实物照片 `arm.jpg` **目测**的（比例近似，单位 mm）：

```
安装板 ─┬─ J1 底座回转 (绕 Z)
        └─ 立柱
            └─ J2 丝杆升降 (绕 Y, 0..90°，蓝胶带模块 = 大臂)
                └─ J3 肘部 (大圆盘, 绕 Y)
                    └─ 细连杆
                        └─ J4 腕俯仰 (末端圆盘, 绕 Y)
                            └─ J5 腕部 (前臂长轴)
                                └─ J6 夹爪 (直线开合)
```

### 4.2 怎么改成你量到的真实尺寸（保存 / 导入 / 重置）

右侧 **模型** 标签页顶部有四个按钮：

| 按钮 | 作用 |
|---|---|
| **保存为默认** | 把当前参数写进覆盖文件，**重启后仍然生效**（有未保存改动时显示 `保存为默认 *`） |
| **导入** | 从本地 JSON 导入模型参数（可接「导出」的文件，也可接 `GET /api/model` 的响应） |
| **导出** | 把当前参数下载成 JSON（备份 / 发给别人 / 进版本控制） |
| **重置** | 删掉覆盖文件，回到 `model_config.py` 的出厂值 |

工具栏下方**直接显示保存路径**和"有没有未保存的改动"，不用猜。

**参数改动怎么落地？**

* **临时看效果** —— 直接改，即时生效（只存在浏览器内存里，刷新即失）；
* **确认后固化** —— 点「保存为默认」→ 写入 `webui/model_overrides.json`
  → 下次启动服务自动加载。

为什么用**覆盖文件**而不是回写 `model_config.py`：

* 不把 Python 源码当数据库写（写坏一个字符服务就起不来）；
* 想恢复出厂值只需删文件（或点「重置」）；
* 覆盖文件是普通 JSON，可直接看 / 手改 / 进版本控制；
* 优先级 `model_overrides.json` > `model_config.py`。

**保存的内容**：旋转轴、连杆长度（pivot）、零位偏移（home_deg）、
夹爪开/闭间距、**伺服软限位**。保存时做完整校验（段数、joint 顺序、
零向量轴、home_deg 范围、夹爪闭合<张开、软限位 lo<hi 且计数不超 ±20000），
**校验不过就不落盘**。

### 4.3 看得清不清（显示选项）

3D 视图左上角有一排开关：

| 开关 | 作用 | 建议 |
|---|---|---|
| 网格 | 地面参考网格 | 开 |
| 坐标轴 | 世界 XYZ（已压暗到 62%） | 开 |
| 关节 | 每个关节轴心的小球（可点选） | 开 |
| 轨迹 | 工具尖端的运动轨迹 | 开 |
| **连杆** | **L1/L2/L3 连杆标注**（琥珀色，便于和实物对照） | **开** |
| **描边** | 反向外壳描边，保证轮廓清晰 | **开**（看不清时先确认它是开的） |
| 景深 | 远处的轻微雾化（很弱） | 开；若觉得发灰就关掉 |

配色在 `webui/model_config.py` 的 `COLORS` 里，都是偏亮的灰调，
**比背景亮得多**（最小 1.9× 亮度差）。改暗会重新变回"看不清"，
但改完跑 `node tests/test_model.js` 就会告警。

### 4.4 模型转向与实物相反？

实物关节的传感器有符号（`reg0x01` 有符号计数），而这个符号对应"往上还是往下"
是逐关节标定出来的，很容易弄反。**每张关节卡片上有一条「模型标定」行，两个按钮**：

| 按钮 | 数学 | 什么时候用 |
|---|---|---|
| **⇄ 反向** | `θ → −θ` | 模型**动起来方向**和实物相反 |
| **↻ 转180°** | `θ → θ+180` | 方向对，但**整体差了 180°**（模型把前臂画成折回来） |

两者**不是一回事**：`−θ` 是镜像，`θ+180` 是旋转。同一个 14.8°：

```
⇄ 反向   ->  -14.8°  ≡ 345.2°   （镜像）
↻ 转180° -> 194.8°               （旋转）
```

点完即时生效，相机视角不变。**改完要点「保存为默认」才会持久化**（见 §4.2）。

更直观的检查：3D 视图右上角的 **「连杆夹角 (L1↔L2 / L2↔L3)」** 直接给数字，
不用靠眼睛估。

**实物规律（2026-09-13 用户截图确认）**：

| J3 传感器 | 实物 L1↔L2 几何夹角 |
|---|---|
| **0°（收拢）** | **180°（两杆完全折回）** |
| 27.75° | 152.25° |
| 90° | 90° |
| **180°** | **0°（两杆共线）** |

即 **`L1↔L2 = 180 − J3传感器值`**。角度变大时 L2 绕 J3 **顺时针**转
（从正面看，J2 在 L1 左端）。

> **已修正的三个默认值**（都写在 `tests/test_model.js` 里锁住）：
>
> 1. **J3 `home_deg` = 180**：模型几何的 0° 是"两杆共线"，
>    而实物传感器 0° 是"两杆完全折回" —— 差 180°。
> 2. **J4 `home_deg` = 180**：同理，J4 传感器 180° 时实物 L2/L3 才共线。
> 3. **J3 轴** `[0,-1,0]` → `[0,1,0]`：让角度增大时 L2 顺时针转。

> **关于 J5 的轴**：实测记录里它叫"腕部 roll"，但"pos=0 水平 / pos=90 垂直"
> 这个现象用"平面内摆动（pitch）"也能解释。默认按 roll 建模；
> 如果你的实物看起来不对，在模型面板把 J5 的旋转轴从 `X` 改成 `Y` 试一下。

### 4.5 预期姿态预览（半透明幽灵模型）

你在关节卡片里改「目标」角度（输入框或滑条）时，3D 视图会立即多出一个
**半透明模型**，它就是“发完命令后机械臂应该在的位置”。
点「移动到目标」后，实体模型会逐步逼近并与它重合。

几个刻意的设计：

| 行为 | 为什么 |
|---|---|
| 预览与你输入的目标**实时同步** | 不用发命令就能先看一眼 |
| 目标与实际**一致时自动隐藏** | 否则半透明层叠在本体上会发黑、看着脏 |
| 超出软限位 → **变橙色** + 右上角告警 | “这个目标发下去会被拒绝”，提前告知 |
| 当前末端 → 目标末端有**虚线引导** | 一眼看出位移量与方向 |
| 目标尖端小球**不做深度测试** | 被本体挡住时也能看到 |
| 脉冲关节（J1/J2）与夹爪**不参与预览** | 它们没有可预测的绝对目标，预览只会骗人 |

**为什么滑条范围等于 SDK 软限位**：只有两者一致，“预览重合”这个承诺才成立。
若滑条能给一个 SDK 会拒绝的角度，你看到的姿态就不会实现。
`webui/model_config.py` 直接从 `robot_arm.registers.SERVO_CALIBRATION` 取边界，
`tests/test_webui.py::test_servo_soft_limits_come_from_the_sdk` 把这个一致性锁住了。

需要更大范围？到「模型」页的**伺服软限位**一栏改 lo/hi（单位 count，相对上电零点），
点「应用」即刻生效（需要先解锁）。⚠ 这是安全边界，**只能在你实测过行程之后放宽**。

### 4.6 角度从哪来

| 关节 | 反馈 | 模型角度 |
|---|---|---|
| J3/J4 | 连续计数 | `pos × 0.09°` |
| J5 | 连续计数 | `pos × 0.237°` |
| J1 | 分区 0/45/90 | 映射到 −90° / 0° / +90°（**估计值**） |
| J2 | 分区 0/45/90 | 0° / 45° / 90° |
| J6 | 0/45/90 | 夹爪开合插值 |

> J1/J2 **没有连续位置反馈**，3D 里显示的是分区映射值 —— 面板上会标明 `zone`。
> 离线关节**保留上一次的角度**（而不是归零），避免误判。

## 5. 安全设计

界面在 SDK 已有的安全机制之上再加了两道闸门：

| 层 | 机制 | 说明 |
|---|---|---|
| 1 | **SDK 传输层闸门** | `reg0x05`、广播/维护地址、复位魔法字 —— 从 HTTP 层也绕不过去 |
| 2 | **运动锁** 🔒 | 默认锁定；必须点右上角解锁才能下发运动命令。按 `Esc` 立即重新锁定 |
| 3 | **`confirm: true`** | 所有运动类 HTTP 接口都要求请求体带该字段，缺了返回 **HTTP 428** |
| 4 | **服务端记录** | 每条运动命令都写进日志（含参数与结果），可导出 |

另外：

* **急停按钮**在任何状态下都可用（不需要解锁、不做身份校验）；
* 停止类按钮在锁定时**依然可用**（停止永远不该被锁住）；
* 司服关节的"停止"会**失去保持力矩**，按钮上直接标注了 `停止(失力)`，
  卡片里也有 `⚠` 提示；
* J2 的下行时长输入框 `max` 被限制在 2.5 秒（SDK 侧还会再拦一次）。

## 6. HTTP API

| 路径 | 方法 | 说明 |
|---|---|---|
| `/` | GET | 控制页面 |
| `/static/<file>` | GET | 静态资源（有目录穿越防护） |
| `/api/model` | GET | 关节语义 + 3D 几何（已合并覆盖文件） |
| `/api/model/save` | POST | `{model}` 校验并写入覆盖文件（需 confirm） |
| `/api/model/reset` | POST | 删除覆盖文件，回出厂值（需 confirm） |
| `/api/state` | GET | 连接状态 + 状态快照 |
| `/api/ports` | GET | 可用串口 |
| `/api/logs?limit=N` | GET | 历史日志 |
| `/api/events` | GET | **SSE** 事件流 |
| `/api/connect` | POST | `{port, baud, dry_run, timeout, retries}` |
| `/api/disconnect` | POST | `{estop_first}` |
| `/api/verify` | POST | 校验 6 个关节固件身份 |
| `/api/refresh` | POST | `{tries}` 只读刷新 |
| `/api/estop` | POST | 急停（需 confirm） |
| `/api/read` | POST | `{slave, start, count}` Debug 原始读 |
| `/api/move` | POST | `{joint, mode, value, speed}` mode = `abs`/`rel`/`counts`/`rel_counts`（需 confirm） |
| `/api/servo/stop` · `/api/servo/enable` | POST | `{joint}`（需 confirm） |
| `/api/servo/limits` | POST | `{joint, lo, hi}` 计数；改 SDK 软限位（需 confirm） |
| `/api/j1/rotate` | POST | `{direction, seconds}`（需 confirm） |
| `/api/j1/stop` | POST | （需 confirm） |
| `/api/j2/pulse` | POST | `{direction, seconds}`（需 confirm） |
| `/api/j2/stop` | POST | （需 confirm） |
| `/api/gripper` | POST | `{action: open\|close, speed}`（需 confirm） |
| `/api/gripper/stop` | POST | （需 confirm） |

响应统一是 `{"ok": bool, "result"|"error": ...}`。
运动接口失败返回 **409**，缺 confirm 返回 **428**，参数错误 **400**，未找到 **404**。

示例：

```bash
curl -s localhost:8765/api/connect -H 'Content-Type: application/json' \
     -d '{"port":"COM8","baud":115200}'
curl -s localhost:8765/api/move -H 'Content-Type: application/json' \
     -d '{"joint":5,"mode":"abs","value":90,"confirm":true}'
curl -s localhost:8765/api/estop -H 'Content-Type: application/json' -d '{"confirm":true}'
```

## 7. 日志与 Debug

### 日志面板
* 分级：`info` / `warn` / `error` / `sdk` / `debug`，可勾选过滤；
* 环形缓冲保留最近 2000 条（服务端），页面保留最近 1200 条；
* 支持**导出为 txt**（带时间戳与等级）。

日志里能看到完整因果链：

```
-> move J3 abs 45.0
  write slave3 reg0x0A = 0x00FA ok
  write slave3 reg0x08 = 0x0001 ok
  write slave3 reg0x0B = 0x01F4 ok
<- move J3 abs 45.0 ok (3.62s)
```

### Debug 面板
* **原始寄存器读取**：任选从站/起始/数量，结果按格子展示
  （同时给出无符号 16 位与有符号解释），用来对照《规格书》的寄存器表；
* **协议帧 trace**：勾选后记录每一对 Modbus 请求/应答的原始 hex，
  排查 CRC 错误、从站不应答、总线噪声时非常有用。

## 8. 测试

```bash
python tests/test_webui.py        # 55 例：路由 / confirm 闸门 / 控制器 / SSE / 前端接线 / 软限位一致性
python tests/test_offline.py      # 36 例：SDK 本身（CRC 回归、安全闸门、换算…）
node    tests/test_model.js       # 40 例：矩阵、正运动学、配色可读性、图元绕序
```

`test_webui.py` 会启动**真实的 HTTP 服务**，并把 SDK 的串口换成 `FakeTransport`，
所以"连接 → 移动 → 急停"是全链路走通的，不需要机械臂。
`test_model.js` 会自己调用 `tests/dump_model_json.py` 取真实模型配置做校验。

## 9. 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 页面显示"无法初始化 WebGL" | 浏览器不支持 WebGL；控制与日志仍可用。换 Chrome/Edge/Firefox |
| 连接成功但"在线关节 0/6" | 机械臂没上电、串口选错、或 A/B 线接反 |
| 某个关节"离线" | 该通道挂死了（历史上运动中轮询/下行超时会导致）；给那块板断电重启 |
| 点了按钮没反应 | 看右下角 toast 和日志面板；多半是"运动已锁定" |
| 帧 trace 里全是 TX 没有 RX | 从站不应答；检查地址、波特率、总线终端电阻 |
| 3D 模型姿态和实物对不上 | 到"模型"面板改轴/连杆长度；某轴**转向相反**就点关节卡片右上角的 `⇄` |
| 机械臂在深色背景上看不清 | 确认左上角 **描边** 开着；仍不行就把 `model_config.py` 的 `COLORS` 整体调亮（跑 `node tests/test_model.js` 会告诉你够不够亮） |

## 10. 已知限制

1. **没有逆运动学**：J2 只有分区反馈、J1 没有连续反馈，无法做可信的
   "给定 XYZ 求解关节角"。3D 视图是**正向**显示（真实读数 → 姿态）+ 关节直接控制。
   尖端坐标是正向运动学的输出，仅供参考。
2. **J1/J2/J6 的模型角度是分区映射**，不是真实角度。
3. **几何尺寸是照片目测**，不是实测；需要按 §4.2 标定。
4. **单客户端语义**：多个浏览器可以同时看，但命令是全局串行的
   （谁先提交谁先执行），没有做权限隔离。
5. `--host 0.0.0.0` **没有鉴权**，局域网内任何人都能控制机械臂；只在可信网络里用。
6. 页面刷新会丢失 3D 轨迹历史（服务端日志仍在）。
