## 1. 硬件 / 协议

| 项 | 值 |
|---|---|
| 固件 | `gd32_firmware_2.bin`（bootloader @0x08000000，app @0x08008000，reset 0x08009728） |
| 板子 | 关节 2 与关节 3 之间连接臂上的双通道 MCU |
| 从站地址 | **2 = 关节 2**，**3 = 关节 3** |
| 总线 | COM8，115200 8N1，RS485（USART3，方向脚 GPIOA.12） |
| 协议 | Modbus RTU：`0x03` 读保持、`0x06` 写单、`0x10` 写多，CRC16-Modbus |
| 寄存器 | 每个地址 **36 个 16 位寄存器**（页基址 `0x2000063C`，步长 `0x48`） |

**上电身份校验（写命令前必须先读）**：`reg0x19==2`、`reg0x1B==0x67C6`、`reg0x1C==0xD81D`、`reg0x17==0`。
来源：固件 `0x0800B42C` 初始化时显式写入这 4 个字。

## 2. 寄存器表（实测）

| reg | 读/写 | 含义 | 实测证据 |
|---|---|---|---|
| **0x00** | R | 当前速度（内部单位，与 `0x0A` 同量纲） | 运动中稳定在 ±250，到位归 0 |
| **0x01** | R | **当前位置（计数，有符号 16 位）** | 0 → −498 → 0，跟随目标 |
| **0x02** | R | **负载/力矩类反馈**（**不是位置误差**） | 静态驱动关闭 ~10；顶硬限位 ~400；**运动刚结束的冲高 / 保位对抗重力 800~1000+**；用手强扭 ±1000 |
| 0x03 | R | 保留 | 读 24~26 |
| 0x04 | R | 同 0x02（镜像） | 与 0x02 同值 |

> ⚠ **2026-09-13 更正**：`reg0x02` 以前被记作"位置环误差"，实测证明它是
> **负载/力矩类反馈**（与 fw2 静态分析 "filtered current-related control feedback" 一致）。
> 它**不能单独用来判"卡住"** —— 运动刚结束时必然冲高（曾误报为堵转，中止了一次移动）。
> 判"卡住"要看**位置偏差**。SDK 已按这个顺序判断，并提供 `ServoState.load` 别名。
| **0x05** | W | ⚠⚠ **危险命令**：`0xAA11` = **回零，目标被固定为 −2700** | 实测：一写就以 ~81°/s 自己跑，且**忽略之后写入的 `0x0B`**；−2700 已超出可达范围 → 顶限位堵转 |
| **0x07** | R/W | **模式**（1 = 位置模式，上电默认 1） | `0x0800C51C` 初始化写 1 |
| **0x08** | R/W | 运行/使能标志（写 0 = 关输出，见 §5） | 上电默认 1 |
| 0x09 | W | 启动命令 `0x1234`（**本次测试未使用**） | `0x0800C274` 启动路径 |
| **0x0A** | W | **速度上限**（内部单位，最大 **732**） | 写 250 → 实测速度贴 250 |
| **0x0B** | W | **绝对目标位置（计数，有符号）— 写它即运动** | 见 §3 实测 |
| 0x13 | R | 1500（默认参数） | |
| 0x14 | R | 1000（默认参数） | |
| **0x17** | R | **故障**（0 = 正常） | 全程 0 |
| 0x19/0x1A | R | 2 / 2（身份） | |
| 0x1B/0x1C | R | 0x67C6 / 0xD81D（身份） | |

## 3. 实测记录（2026-09-12）

### 换算关系（★ 2026-09-13 现场重新标定）

**零点 = 完全收拢姿态**（上电即收拢，行程**单向** `0 -> +N`）。两点法实测：

| 物理角度 | 原始计数 | 来源 |
|---|---|---|
| **0°（收拢，限位触发）** | **1** | 3 次采样稳定 |
| **180°** | **1785** | 用户目测到 180° 后读取 |

```
(1785 - 1) / 180 = 9.9111 count/deg  ->  0.100897 deg/count
旧文档写的 0.09 deg/count 偏小 11%    <- 已废弃，见下方历史记录
```

标定工具：`python analysis/encoder_calibration.py --joint 3 --deg 180`
（只读不驱动；连读 3 次一致才记录；数据存 `analysis/encoder_calibration.json`）

**为什么这不只是精度问题**：旧率下 `move_to_deg(250)` 会下发 2778 count，
而 2778 count 实际是 **280°** —— 已经越过 270° 的底座干涉线。

标定后的软限位（用**原始计数**存，避免换算率误差影响安全边界）：

| 关节 | `deg_per_count` | `zero_counts` | 软限位（计数） | 对应角度 |
|---|---|---|---|---|
| **J3** | 0.100897 | 1 | **(1, 2479)** | 0 .. 250.0°（270° 会撞底座）|
| **J4** | 0.100897（推定同 J3） | 8 | (8, 1500) | 0 .. 150.5°（远端未标定）|
| J5 | 0.237 | 0 | (0, 681) | 0 .. 161.4°（未重标）|

> ⚠ 零位来自**上电瞬间**。下次必须以收拢姿态上电，这套标定才成立。

### 两次闭环移动

| 次数 | 方向 | 起始 pos | 目标 pos | 实际到位 | 静差 | 用时 | 速度符号 |
|---|---|---|---|---|---|---|---|
| 1 | 正转 | 0 (0°) | −500 (−45°) | −498 (−44.8°) | +2 | 3.5 s | vel −250 |
| 2 | 反转 | −498 (−44.8°) | +2 | **0 (0.00°)** | −2 | 3.8 s | vel +250 |

- 全程 `reg0x17 = 0`（无故障），速度呈标准梯形规划（加速→匀速→减速到 0）。
- **往复回到原点误差 ≤ 2 计数 ≈ 0.18°**。
- 速度上限 250 时，位置速率约 **150 计数/秒 ≈ 13.5°/秒**；上限 732 ≈ **39°/秒**。
- 速度寄存器单位与计数/秒不成 1:1（250 内部单位 ≈ 150 计数/秒，比例约 1.67），是"内部单位"。

### 上电参考位置（重要）
用户在上电**前**手动把关节 3 拧到约 **90°（垂直）**；上电后 `reg0x01` 读到 **0/1**。
→ **计数 0 ≈ 上电时的物理位置（约 90° 垂直）**。
待确认：这是"上电清零"还是"绝对编码器 + 固定零位"（需断电再上电对比）。

### 行程范围（实测，2026-09-12）
以某次上电位置为零点，步长 20° 向两侧推进，实测两端都被**真实机械限位**挡住：

| 方向 | 可走到 | 受阻点 | 相对参考点 |
|---|---|---|---|
| 负方向 | −441 ✓ | **−560** | **≈ −50°** |
| 正方向 | +1997 ✓ | **+2154** | **≈ +194°** |

**总行程 ≈ 2154 − 560 = 2714 计数 ≈ 244°**（用户目测约 300°，量级一致）。
注意：这个范围是**相对当次上电参考点**的，换一个上电位置，两端数值都会平移。

### 停止/失能（实测确认）
写 **`reg8 = 0`** → 固件执行 `0x0800C2D0 → 0x0800C1C0`（清 CCER）→ **三路 PWM 输出关闭**。
实测 `reg0x02` 从 4497 骤降到 14，证明堵转推力立刻消失。
**代价：失去保持力矩，重力负载会下垂。**

## 3f. 关节 5（腕部 roll）✅ 也是位置伺服！

**突破性结论**：关节 5 与关节 4 **同一固件构建号 `0xD824`**，也是**位置伺服**，
而不是早先（`archive/` 与 `joint5_6_dual_channel_findings_2026-09-12.md`）以为的
“定时方向状态机”。之前的困惑至此解释清楚：那时写 `reg5=0xAA11` 让 roll 转到水平，
其实正是固件里的**“回零”命令**。

### 与关节 3/4 的关键区别（已实测）

| 项 | 关节 3/4 | **关节 5** |
|---|---|---|
| 上电 `reg0x07` mode | 1（位置模式） | **0** |
| 上电 `reg0x08` run | 1（已使能） | **0（未使能）** |
| 上电 `reg0x0A` speed | 732 | **0** |
| 写 `reg0x0B` 是否自动使能输出 | ✅ 会 | ❌ **不会**（必须显式 `reg0x08=1`）|

**因此关节 5 必须按这个顺序操作**（`joint3.py` 已自动处理）：

```
reg0x07 = 1   (位置模式)
reg0x0A = 速度上限
reg0x08 = 1   (使能)
reg0x0B = 目标位置   ← 此时才会动
```

### 标定与限位

| 项 | 值 |
|---|---|
| 角度换算 | **1 count ≈ 0.237°**（≈ 4.23 counts/度）—— 
| | 实测：`pos=0` → 0°（夹爪与连接臂水平）；`pos=676` → ~160°；最大接近 180° 翻转 |
| 行程 | **≈ 681 计数 ≈ 161°**（软限位窗口 [0, 681]）|
| 固件软限位窗口 | **[0, 681]** |
| 负方向端点 | **0**，机械上已到底（再往下 err 会累积推不动）|
| 正方向端点 | ≈676（`err=0` 干净停机）|

### 固件的“钳位/回退”行为（重要）

| 写入 `reg0x0B` | 读回 `target` | 说明 |
|---|---|---|
| 1500 | **681** | 超上限 → 被钳位 |
| −1000 | **0** | 越界 → 回退到当前位 |
| −200 / −50 | −200 / −50 | 接受，但机械上推不动（err 累积）|
| 0 | 0 | 正常 |

### 实测

| 动作 | 结果 |
|---|---|
| `0 → 333`（40°）| 到位 **330**（静差 3），`err=0`，`fault=0` ✅ |
| `330 → 0` | 到位 **0**（静差 0），`err=0` ✅ |
| `0 → 380`（**90°**）| 到位 **377**，用户确认**正好垂直 90°** ✅ **标定验证通过** |

**参考位置**（已确认）：
- `pos=0` → **0°**，夹爪与连接臂**水平**
- `pos=377` → **90°**，夹爪**垂直**
- `pos=676` → **≈160°**，接近 180° 翻转

**换算（已验证）**：`角度(°) = 计数 × 0.237`，即 `1° ≈ 4.23 计数`。

**用法**：`python joint3.py --slave 5 --speed 200 move --deg 40 --yes`（模块自动做模式/使能设置）。

```text
读全部 36 寄存器      : 03 03 00 00 00 24 44 33
速度上限 = 250        : 03 10 00 0A 00 01 02 00 FA 3F D9
速度上限 = 732(满)    : 03 10 00 0A 00 01 02 02 DC BF 63
目标 = 0              : 03 10 00 0B 00 01 02 00 00 BE 4B
目标 = -500 (-45°)    : 03 10 00 0B 00 01 02 FE 0C FE 2E
目标 = +500 (+45°)    : 03 10 00 0B 00 01 02 01 F4 BE 5C

```

换算：`目标计数 = round(度数 × 11.111)`，负角度取 `& 0xFFFF`。

## 5. 安全注意（都踩过坑）

1. **停止 = 写 `reg8=0`**。它会真正关闭三路 PWM 输出，关节**失去保持力矩、重力负载下会下垂**，
   停止前先支撑机械臂。（`reg0x02` 从几千掉到几十可作为"确实停止了"的判据。）
2. ⚠⚠ **绝对不要写 `reg5 = 0xAA11`**：这是"回零到 −2700"命令，会以 ~81°/s 自走并**忽略 `0x0B`**，
   极易顶到限位堵转。
3. **`addr=0xAA` + 值 `0xAA55` 会触发系统复位**，不要误写。
4. ⚠ **运动过程中不要轮询**：在运动（尤其是 `reg5` 触发的回零）中连续读，会让从站**挂死**，
   必须断电重启。安全做法：**发命令 → 静默等待足够时间 → 只读一次**。
   低速小步长（≤10 Hz）在这些关节上一般可行，但**不要赌**。
5. 两端都是**真实机械限位**。超过就会堵转（电流上升、`reg0x02` 累积到几千）。
   命令前先算好目标是否在可达范围内。
