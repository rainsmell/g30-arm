# 关节 2 控制接口（丝杆摆臂）★已摸清

> 硬件：与关节 3 同一块双通道板，Modbus 从站地址 **2**；固件 `gd32_firmware_2.bin`。
> 身份校验与关节 3 相同：`reg0x19=2`、`reg0x1B=0x67C6`、`reg0x1C=0xD81D`。
> 工具：`analysis/joint2.py`
> 更新：2026-09-12

## 0. 一句话总结

**电机 → 丝杆 → 滑块 → 推动关节旋转**（像挖掘机的大臂）。
固件只提供**"方向 + 限位"**接口：`reg0x0B` 选方向并启动，两端靠**两个限位开关**判断；
`reg0x01` **不是位置，而是限位开关的状态编码**，没有连续角度反馈。

## 1. 寄存器表（实测）

| reg | 读/写 | 含义 | 备注 |
|---|---|---|---|
| 0x00 | R | 速度类 | 恒读 0，基本无用 |
| **0x01** | R | **限位开关状态编码 0 / 45 / 90** | 见 §2 |
| **0x02** | R | 运动指示 | 运动中 ~130~155；静止 0 |
| 0x03 | R | 保留 | 0 |
| 0x04 | R | 保留 | 0 |
| **0x07** | R | 模式 = **0** | 与关节 3（=1）不同 |
| **0x08** | R/W | 使能/运行标志 | **写 0 = 关闭输出** |
| 0x0A | — | **未使用**（读 0） | 关节 2 无速度寄存器 |
| **0x0B** | W | **方向 + 启动：`1` = 上行，`0` = 下行** | 见 §3 |
| 0x13 / 0x14 | R | 700 / 400（默认参数） | 由 `0x0800BB48` 写入 |
| 0x17 | R | 故障（0 = 正常） | 全程 0 |
| 0x19/0x1A | R | 2 / 2（身份） | |
| 0x1B/0x1C | R | 0x67C6 / 0xD81D（身份） | |

底层驱动（静态确认）：**直流电机 + H 桥**，PWM 走 **TIMER2 CH0/CH1**，速度钳位 [-99, +100]：
`0x0800CD1C(motor=2, speed)`：速度 >0 用 CH1，<0 用 CH0，=0 两路都 0。

## 2. `reg0x01` 的语义（★关键）

**这不是位置，是两个限位开关的状态编码：**

| `reg0x01` | 含义 | 物理 |
|---|---|---|
| **90** | **上限位开关被压下** | 行程上端，滑块在丝杆末端，臂**垂直** |
| **45** | 两个开关都没压下 | 行程中间 |
| **0** | **下限位开关被压下** | 行程下端，滑块在丝杆另一侧，臂**接近水平** |

证据：

- 上行实测 `0 → 45 → 90`（离开下限位 → 中间 → 到达上限位）；
- 下行实测 `90 → 45 → 0`；
- **用户手动按住下限位开关时，关节明明在 ~80°，寄存器仍读 0** ✓
  —— 证明它是"标志位"，不是角度。

### 2.1 ⚠⚠ `reg0x01` 不可信，**绝对不要用它做"走到限位自动停"**（2026-09-13）

当天连续实测发现分量与实际位置到处矛盾：

| 脉冲 | 命令 | **用户目测的真实位置** | 读到的 `reg0x01` | 一致？ |
|---|---|---|---|---|
| 起始 | — | **垂直（行程最上端）** | `0` | ❌ |
| 1 | `reg0x0B=0` | 垂直 → 45° | `45` | ✅ |
| 2 | `reg0x0B=0` | **45° → 0°（到底）** | `45` | ❌ |
| 3 | `reg0x0B=1` | 0° → 45° | `45` | ✅ |

两点结论：

1. **方向映射是对的**：`reg0x0B = 0` = 下行，`reg0x0B = 1` = 上行（用户目测确认）。
2. **`reg0x01` 在两端都不可信**：实物在**最上端**时读 `0`（看起来像"下限位触发"），
   实物在**最下端**时读 `45`（看起来像"什么都不触发"）。

**原因（已由用户现场确认，2026-09-13）**：**关节 1 松垮**。
J1 的机械间隙/松动导致传向 J2 下限位开关的连动机构错位，
所以 **J2 实际走到 0° 时根本压不到下限位开关**。
这也是为什么开关会在“臂垂直（最上）”时反而读成压下的。

（补充实验：把 J1 抑制（`reg0x1F=1`）后 J2 的 zone 依旧为 45，
说明不是 J1 的驱动力顶的，而是机械装配的静态错位。）

> **安全结论（强制）**：
> - **禁止使用“跑到限位自动停”（`run_until_limit`）** —— 限位信号不可信，
>   会直接跑到机械死点堵转 → 3.2 s 后过速保护硬刹车 → 从站挂死。
> - J2 一律用**短脉冲（≤ 2.5 s）+ 人工目测**定位（`examples/lower_joint2.py`）。
> - 要重新相信 `reg0x01`，**必须先修 J1**（否则两个轴的反馈都不可信）。

## 3. 命令与运动

| 动作 | 命令 |
|---|---|
| 上行 | 写 `reg0x0B = 1` |
| 下行 | 写 `reg0x0B = 0` |
| 停止 / 关输出 | 写 `reg0x08 = 0` |
| 使能 | 写 `reg0x08 = 1` |

- 上行：固件驱动到**上限位开关**动作后干净停止（实测每次都到 90）。
- 下行：固件驱动到**下限位开关**动作后停止。
- **没有"目标位置"寄存器**：要停在中间只能靠"脉冲时长 + 人工观察"。

## 4. 挂死原因（★★已定案）

| 条件 | 下行长时间运行 |
|---|---|
| 下限位开关**未触发**（悬空/没按到底） | ❌ **挂死**（4/4 次，必须断电） |
| 下限位开关**使劲按到底** | ✅ **不挂死**（2/2 次，5 秒下行也正常） |

机理：下限位开关很硬，未按到底时固件收不到"到位"→ 一直往下推 → 滑块顶到丝杆末端机械死点
→ **电机堵转，电流冲击** → 单片机挂死（固件另有"超速→两路 H 桥同时 100% 短接刹车"的保护路径
`0x0800CCF0`，会进一步加剧电流冲击）。

> **已解决（2026-09-13）**：底板连接件装回后，下行可以一次走到底并**干净停在限位开关**：
> 实测「从 pos=90 一路下行 8 秒」→ 到达 **pos=0**、`err=0`、`fault=0`、**从站正常响应（不挂死）**。
>
> 待办里保留的警告仍然适用：**如果机械上无法让开关被压下**（例如被其他关节挡住，
> 或底板再次拆除），长时间下行仍会堵转挂死。此时请用短脉冲（`joint2.py`）。

## 5. 安全操作规则

1. ⚠ **下行必须用短脉冲**（`joint2.py` 硬性限制 ≤ **2.5 秒**），脉冲后立即 `reg8=0`；
   或者确认下限位开关一定能被压下，才可以让它一次走到底。
2. ⚠ **运动中不要读取长帧**（36 寄存器）——实测会挂死；用"发命令 → 静默等待 → 只读一次"。
3. ⚠ **禁止写 `reg0x05`**（`0xAA11` 是危险的回零命令），禁止 `addr=0xAA + 0xAA55`（系统复位）。
4. `reg0x08=0` 会关闭输出（丝杆自锁，不会自己下滑）。

## 6. 工具 `analysis/joint2.py`

```bash
python joint2.py status                    # 只读
python joint2.py up   --seconds 2.5 --yes  # 上行脉冲
python joint2.py down --seconds 1.5 --yes  # 下行脉冲（≤2.5s）
python joint2.py stop                      # reg8=0
```

内部：自动 `enable → 写方向 → 等待 → reg8=0 → 静默 → 单次读`，并硬性拒绝超过 2.5 秒的脉冲。

## 7. 验证结果（2026-09-13）

| 测试 | 结果 |
|---|---|
| 上行 0 → 45 → 90（两次脉冲） | ✅ 干净，无挂死 |
| **下行 90 → 0，一次跑 8 秒（靠限位开关停）** | ✅ **到位 pos=0，`err=0`，不挂死** |
| 下行时被其他关节（关节 3）机械挡住 | ❌ 仍会堵转挂死（与开关无关，是机械干涉）|

**结论**：只要机构能让**下限位开关被压下**，下行就没问题；被挡住/开关无法触发时才会挂死。
